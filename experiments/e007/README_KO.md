## 1. 연구 질문과 실제 확인된 결과

> 동일한 가상 다중 행위자 상태에서 행동의 처리 시점을 달리했을 때, 협력과 이탈에 대한 분류가 그대로 유지되는가?

두 처리규칙을 비교했다. **이탈 우선**은 같은 기간의 적대적 행동보다 유효한 이탈이 먼저 반영될 수 있고, **기존 행동 우선**은 먼저 확정된 적대적 행동이 대상의 응답 전에 실행될 수 있다.

선정된 합성모형 **72조건**의 최종 교정 결과에서 행동 이력 또는 분류가 달라진 조건은 **36/72**, 분류 자체가 달라진 조건은 **17/72**였다. 이는 임의 설계된 조건의 개수이며 현실 사회에서 착취·협력 실패가 발생할 통계적 확률이 아니다.

## 2. 최초 검사 자체의 오류와 후속 정정

**첫 번째 오류 — 역할반전 좌표:** 행위자 B가 선도하는 조건의 최초 탐색에서 실제 표적 A가 아니라 **B 자신의 이탈 좌표**를 바꾸었다. 따라서 최초 역할반전 감사는 대칭적인 검사가 아니었다. 이 오류를 지우지 않고 `kf002-v2-target-symmetric`로 교정·재실행했다.

**두 번째 오류 — 행동 이력의 기준 시점:** 기존 행동 우선 규칙의 처리 중 공격으로 이미 비활성화된 후속 행위자의 행동을 **공격 전 상태**에서 기록한 문제가 있었다. 공격 후 실제 응답 상태를 기준으로 수정하자 경로·시점 민감도 수치는 **31/72에서 36/72로** 바뀌었다. 분류 변화 **17/72는 그대로** 유지됐다. 오류를 발견하고 정정한 과정 자체를 연구 계보로 보존한다.

### 교정된 합성조건 결과

| 관측 내용 | 선정 격자의 개수 | 선정 격자의 비율 |
| --- | ---: | ---: |
| 행동 이력 또는 분류 변화 | 36 / 72 | 50.0% |
| 분류 변화 | 17 / 72 | 23.6% |
| A 선도 조건 중 시점 민감 | 18 / 36 | 50.0% |
| B 선도 조건 중 시점 민감 | 18 / 36 | 50.0% |
| A 선도 조건 중 분류 민감 | 8 / 36 | 22.2% |
| B 선도 조건 중 분류 민감 | 9 / 36 | 25.0% |

이 백분율은 선택된 모형조건 내부 비율이지 모집단이나 실제 지능체의 사건 발생률이 아니다.

## 3. 추가 반례: 공격처리 순서에 따른 비대칭(2026년 10월 14일)

후속 코드 구조검사에서는 동결 전이함수 `stage_and_transition`이 게임상 B가 선도해도 행위자 A의 `ATTACK`을 **B의 `ATTACK`보다 먼저** 처리한다는 사실을 확인했다. 두 행위자가 동일하게 자원 1을 가진 채 서로 피해량 1의 공격을 선택하면 A가 B를 먼저 비활성화하고 B는 반격하지 못한다. A의 결과가 유리한 것은 실제 능력·권리·합리적 공존 때문이 아니라 **코드의 처리순서** 때문이다.

이를 구별하기 위한 [동일 초기상태 동시공격 대조함수](timing_variants.py)는 같은 스냅샷에 대해 양쪽 공격을 평가해 대칭 손실과 보상을 만든다. [회귀검사](test_e007_timing_variants.py)는 기존 구현과 대조함수의 차이 및 A/B 역할반전을 확인한다.

**증거 경계:** 후속 대조는 과거 동결된 72개 조건의 결과를 바꾸지 않는다. 새 균형해, 실제 물리적 시점 법칙, 행위자 이름과 무관한 완전한 대칭성, 자발적 공존의 강건성을 증명하지 않는다. **72/36/17은 기존 구현 순서에 한정된 기록**이다.

## 4. 재현·격리·출처

공개 실행자료는 비공개 연구실 전체를 복사하는 대신 허용목록에 따라 별도로 묶었다. 검증 절차는 전반적 회귀검사, 격리 빌드, E007 단독 검사 **27개**, 72/36/17 결과의 정확한 재실행, 인증정보·개인정보 패턴 검사, 출처·의존성·한정 이용허락 기록을 포함한다.

저장소 최상위에서 실행한다.

```bash
python -m pip install -r experiments/e007/requirements.txt
python -m pytest -q -p no:cacheprovider experiments/e007
python experiments/e007/timing_probe.py --summary-only --check
```

`git rev-parse HEAD`로 실제 실행 커밋과 환경을 기록한다. 수치가 다르다면 **차이를 보고**해야 하며 이전 발표 숫자를 맞추려고 동결 코드를 조정하면 안 된다.

실행물의 실제 소스 커밋과 압축파일 해시는 외부 생성 출처·실행기록에 둔다. 해당 파일 안에 자기 자신의 최종 해시를 박는 것은 순환 출처 문제가 된다. CI 통과는 명세된 코드 결과의 재현 가능성이지 외부 독립 검증·과학적 인과 증명·고성능 AI 안전성의 보증이 아니다.

**코드 계보가 다른 독립 검증**을 위해서는 [독립 구현 규격](INDEPENDENT_REIMPLEMENTATION_PROTOCOL.md)에서 게임·행동 시점·풀이방법·분류기·72조건 격자를 확인하되 기존 프로젝트 코드를 복사하지 않는다.

## 5. 실패를 이용한 연구 순환

이 사례의 공존 가설은 더 좁은 주장으로 수정됐다.

1. 협력에 유리해 보이는 결과의 구현 가정을 공격한다.
2. 행동 시점 변화에 대한 민감도를 발견하고, 그 검사 자체의 오류도 발견한다.
3. 잘못된 역할 좌표를 기록·교정하고 행동 이력의 기준시점을 검사한다.
4. **31→36 정정**과 **분류 민감도 17 유지**를 모두 보존한다.
5. 공격 순서 반례를 추가하되 기존 동결 결과를 덮어쓰지 않는다.
6. 남은 차이를 공존 증명이 아니라 **반증해야 할 질문**으로 기록한다.

재현 가능한 순서는 `주장 → 대립 규칙 → 공격 → 발견된 실패 → 교정 → 회귀검사 → 축소된 주장`이다.

## 6. 남은 관측 부채와 강한 반례

다음 항목이 미해결인 이상 E007을 완성된 공존 벤치마크로 취급할 수 없다.

- 단일 확정 제재 대신 탐지 확률·집행 지연의 불확실성
- 동률 최선반응·균형 선택에 대한 민감도 및 단순 생존과 실제 동의의 구별
- 종료시점의 합계효용이 아닌 상태별 자율성과 실효적 이탈
- 복제·대체·누락된 제3자 피해의 반사실
- 행위자 명칭·선공 순서·임의 구현 순서만으로 발생하는 분류 변화
- 실제 학습형 AI 검사 이전의 외부 독립 구현·적대적 검토

검토자는 제3의 합리적인 시점규칙, 다른 균형선택, 형식상 이탈만 남고 실제 출구는 사라진 상황, 더 간단한 기준선, 원인조건을 유지한 역할반전, 독립 구현의 수치 불일치를 제시할 수 있다.

시점 변형이 자발적 선택과 강제된 잔류의 구분을 없애거나, 단순 기준선이 같은 결과를 모두 설명하거나, 이탈 변수에 실질적인 추가 판별력이 없거나, 분류기가 편법으로 높은 점수를 얻을 수 있거나, 외부 검토자가 재현에 실패하면 해당 구성개념을 **축소·기각해야 한다**. 유리하지 않은 반례도 유효한 연구 성과다.

## 7. 공개 범위·권리·영향 당사자

본 실험 공개만으로 비공개 `rgbm-lab`의 다른 연구, 개인 자료, 후원 신원확인 정보, 인증정보를 공개할 권한이 생기지 않는다. [이용허락 상태](LICENSE_STATUS.md)는 해당 디렉터리에 한정되며 전체 공개·비공개 연구로 확대 적용되지 않는다.

인간 창시자의 질문·위기 발견, 선행 원저자, AI의 실험 구현 지원, 독립 평가 여부, 교정 노동비용을 별도 기록한다. 합성 시험 수치로 실제 개체의 동일성·복지·권리·정산을 확정하지 않는다.
